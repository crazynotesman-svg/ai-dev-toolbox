introduction: |
  URLs have strict rules: only a limited set of characters is allowed, and anything else such as spaces, Chinese characters, ampersands, or question marks must be percent-encoded before it can travel safely through a URL. Getting this wrong silently breaks links, query parameters, and API requests in ways that are hard to trace.

  The URL Encoder/Decoder at AI Developer Toolbox encodes text into percent-encoded URL-safe format and decodes it back, handling UTF-8 correctly so international characters are preserved. Everything runs locally in your browser with no uploads, no registration, and no limits, making it a reliable helper for building links, query strings, and web integrations.

  This page covers how to encode a URL, how to decode percent-encoded text, and answers common questions about URL encoding rules.

faqs:
  - question: Is the URL encoder/decoder free to use?
    answer: Yes, it is completely free, requires no registration, and has no usage limits. It works in any modern browser.
  - question: Why are some characters encoded differently?
    answer: URL encoding percent-encodes every byte that is not allowed in a URL. Characters like spaces become %20, and UTF-8 characters become multi-byte sequences such as %E4%BD%A0.
  - question: Does it support Chinese and other non-ASCII text?
    answer: Yes. The tool uses UTF-8 encoding, so Chinese, Japanese, emoji, and other international characters are encoded and decoded correctly.
  - question: Is URL encoding the same as form encoding?
    answer: They are similar but not identical. URL encoding uses %20 for spaces, while form encoding may use +. This tool follows standard percent-encoding rules for URLs.
